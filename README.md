# ReviewLab

배달앱·포털 리뷰의 공정성을 연구하는 대학생 팀을 위한 한국어 연구자료 관리 도구입니다. 현재 **1·2단계**를 구현했습니다. 실제 참고문헌은 사용자가 조사하여 입력하며, 앱은 논문을 생성하거나 출처를 자동 검증하지 않습니다.

## 구현한 기능

- 학술논문 / 뉴스기사 / 정부·공공기관 자료 / 플랫폼 정책 / 기타 자료 직접 등록 및 일반 CSV 일괄 등록
- 제목·저자 검색, 유형·태그·검증 상태 필터, 발행일·등록일 양방향 정렬
- 상세 조회, 수정, 확인 후 삭제, 복수 태그 선택 및 태그 추가·이름 변경
- 미검증 / 원문 확인 중 / 검증 완료 / 사용 보류 및 전체 검증 이력
- 자료 수·검증 현황·유형별 그래프·태그별 개수
- SQLite 영속 저장, 변경 후 자동 일별 백업, 한글 목록 CSV, 이력을 포함한 CSV 백업·복원
- 리뷰 CSV 업로드, 프로젝트별 필터·패턴 탐색·연구자 검토, 통계·PNG·CSV 내보내기 및 리뷰 백업
- 로컬 SQLite / Supabase PostgreSQL 공용 저장소 선택, 이메일 로그인·작업공간 권한·RLS·버전 충돌 감지
- 실제 자료와 예시·연습 자료의 별도 DB 또는 공용 모드별 테이블 범위. 자동으로 삽입되는 가짜 참고문헌은 없습니다.

## 노트북·데스크탑에서 공용 자료 사용

**로컬 SQLite**는 현재 컴퓨터에만 저장합니다. 같은 자료를 두 컴퓨터에서 관리하려면 새로 추가한 **Supabase 공용 저장소**를 선택하고 같은 작업공간·실제/예시 모드로 로그인하세요. 기존 자료 등록·일반 CSV 일괄 등록·리뷰 분석·CSV 백업은 두 모드에서 사용할 수 있습니다. 기본값은 로컬이며 연결 오류 때 자동으로 저장소를 바꾸지 않습니다.

공용 DB 연동 코드·Auth·권한·RLS SQL·SQLite 이전 미리보기·충돌 감지·전체 백업 기능을 추가했습니다. **실제 Supabase 프로젝트는 아직 생성/접속하지 않았습니다.** 사용자가 프로젝트와 로그인 계정을 만든 뒤 설정해야 합니다.

**처음 설정하는 순서:** [Supabase 한국어 설정 안내](supabase/README.md)를 따라 프로젝트 생성 → SQL 1회 실행 → Auth 계정 준비 → 각 컴퓨터의 secrets 설정 → 예시 자료로 두 기기 검증 → 실제 SQLite 이전을 진행하세요. 접속 정보를 채팅에 보내지 않아도 됩니다.

앱 메뉴는 왼쪽 **저장소 → Supabase 공용 저장소**, 이전·전체 백업은 **공용 DB 관리**입니다. 공용 대시보드는 약 10초마다 변경을 확인하며 편집 화면은 입력 보호를 위해 알림 후 수동 새로고침합니다. 다른 기기가 먼저 저장하면 오래된 저장은 중단합니다. 현재 충돌 검사는 같은 작업공간의 실제/예시 모드 전체 단위라 서로 다른 자료를 바꿔도 충돌할 수 있습니다.

로컬과 공용은 자동 양방향 동기화하지 않습니다. 원본 SQLite와 이전 전 백업은 유지하며, 이전 시 중복 후보·동일 이름 태그 연결을 확인합니다. 같은 ID의 내용·이력이 다르면 전체를 차단합니다. 공용 기본 제한은 모드별 20MB·50,000개 레코드이며 3~5단계 기능은 아직 구현하지 않았습니다.

## 처음 실행하기

Python **3.12**를 권장합니다. Python 3.11 이상이 필요하며 실제 검증 환경은 Linux/Python 3.12.14입니다. 아래 명령은 저장소를 내려받은 `codex` 폴더에서 실행하세요. Windows/macOS 명령은 안내용이며 해당 OS에서 직접 실행한 검증은 하지 않았습니다.

### Windows 간편 실행

ZIP 파일을 Windows에 **다운로드한 뒤 모두 압축 해제**하고, `app.py`와 같은 폴더의 `Start_ReviewLab.cmd`를 더블클릭하세요. 웹 화면에서 ZIP 미리보기가 지원되지 않는다는 표시는 파일 손상을 뜻하지 않습니다.

실행 파일은 Python 3.12가 있으면 재사용하고, 없으면 Windows의 winget 공식 Python 패키지 설치를 시도합니다. 프로젝트 폴더에 `.venv`를 만들고 필요한 패키지를 설치한 뒤 로컬 서버를 시작하여 브라우저를 엽니다. 실행 중인 명령 창을 닫으면 앱도 종료됩니다. 설치 권한이나 winget을 사용할 수 없으면 Python 3.12를 직접 설치하라는 안내를 표시합니다.

이 파일은 관리자 권한, 프록시·방화벽 변경, PowerShell 실행 정책 변경을 요구하지 않습니다. Windows에서 직접 실행 검증하지는 않았습니다. 실행 오류가 있으면 창이 닫히지 않으므로 오류 내용을 확인할 수 있습니다.

### Windows (PowerShell)

Python 설치 시 “Add Python to PATH”를 선택하고 프로젝트 폴더에서 터미널을 엽니다. 가상환경 활성화 없이 실행하므로 PowerShell 실행 정책 변경이 필요 없습니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

터미널이 안내하는 로컬 주소를 같은 컴퓨터의 브라우저에서 열면 됩니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요. 다음 실행에는 마지막 명령만 다시 실행하면 됩니다. `8501` 포트를 다른 프로그램이 사용 중이면 명령 뒤에 `--server.port 8502`를 붙이세요.

앱은 기본적으로 `127.0.0.1`에만 바인딩합니다. 로컬 모드는 로그인 없이 해당 컴퓨터의 자료를 사용하고 공용 모드는 Supabase 로그인과 권한 검사를 사용합니다. 공개 웹 서버 배포 구성은 제공하지 않습니다. 클라우드의 포트 미리보기 제공 여부는 실행 플랫폼에 따라 다릅니다.

`requirements.txt`는 직접 의존성을 고정합니다. `requirements.lock`은 Linux/Python 3.12에서 검증한 전체 의존성 버전이며, 동일 환경 재현 시 `pip install -r requirements.lock`을 사용합니다. 다른 OS/Python 버전에서 전체 잠금 파일의 호환성은 별도 확인이 필요합니다.

## 처음 사용하는 순서

1. 왼쪽에서 **실제 연구자료** 또는 **예시·연습 자료**를 선택합니다. 연습 내용은 실제 연구에 합산되지 않습니다.
2. **자료 등록**에서 제목·자료 유형·원문 URL을 입력합니다. 이 세 항목이 필수입니다. 저자/기관, 발행일, 핵심 메모, 활용 목적, 태그는 선택 사항입니다.
3. 발행일은 `2025`, `2025-03`, `2025-03-15`처럼 아는 범위까지 입력합니다. 미상은 빈칸으로 둡니다. 자료의 등록 시각은 UTC로 자동 기록됩니다.
4. **자료 목록**에서 검색·필터·정렬 후 자료를 선택해 상세 확인, 수정, 삭제합니다. 중복 후보는 같은 URL 또는 같은 제목·저자·발행일입니다. 별도 자료라면 등록 폼의 중복 허용을 명시적으로 선택할 수 있습니다.
5. **검증 관리**에서 직접 원문을 확인하고 상태를 기록합니다. 검증 완료에는 날짜·담당자(별칭 권장)·확인한 원문/공식 자료·메모·직접 확인 체크가 모두 필요합니다. URL만으로 완료되지 않습니다.
6. **설정 및 데이터 관리**에서 태그를 관리하고, **데이터 백업 및 복원**에서 정기적으로 복원용 CSV를 내려받습니다.

검증 완료 후 자료를 수정해도 기존 이력은 유지됩니다. 변경한 내용에 맞게 검증 상태를 다시 기록하세요. 태그를 수정하면 해당 태그가 연결된 모든 자료에 반영됩니다. 검증 날짜는 실행 컴퓨터의 날짜 기준이며 기록 시각 표시는 UTC입니다.


## 일반 참고문헌 CSV 일괄 등록

외부에서 조사한 참고문헌을 한 번에 등록하려면 **자료 등록 → 등록 방식: CSV 일괄 등록**을 선택하세요. 검증 상태를 포함한 과거 이력을 되살리는 전용 백업 복원과는 다른 기능입니다.

1. 왼쪽에서 **실제 연구자료** 또는 **예시·연습 자료** 모드를 먼저 선택합니다.
2. **일반 참고문헌 CSV 양식 다운로드**를 눌러 빈 양식을 받습니다. Excel에서 열고 두 번째 행부터 조사한 자료를 한 행에 하나씩 작성하세요.
3. **다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)**로 저장하는 것을 권장합니다. 기존 한글 Windows CSV라면 업로드 화면에서 **CP949**를 선택할 수 있습니다. `.xlsx` 파일의 확장자만 `.csv`로 바꾸면 안 됩니다.
4. **일반 참고문헌 CSV 업로드**에서 파일을 선택합니다. 자동 연결한 열, 추가 예정·중복·오류 건수를 확인하세요. 아직 DB에는 등록되지 않습니다.
5. 오류가 있으면 화면의 **CSV 행·오류 원인**을 보고 원본 CSV를 수정·저장한 뒤 다시 업로드합니다. 오류가 한 건이라도 있으면 전체 등록을 차단합니다. 여러 줄로 된 셀도 자료 한 건으로 세므로 CSV 행 번호는 첫 제목 행을 포함한 자료 순번입니다.
6. 현재 모드와 미검증 등록 안내를 확인하고 **CSV 일괄 등록 실행**을 누릅니다. 완료 후 추가·중복·실패 건수를 확인합니다.
7. **자료 목록**에서 제목 또는 저자를 검색하고 태그·자료 유형·검증 상태로 필터링하세요. 원문을 직접 확인한 다음 **검증 관리**에서 상태를 기록합니다.

| 양식 열 | 필수 여부·작성 방법 |
| --- | --- |
| 제목 | 필수 |
| 자료 유형 | 필수: 학술논문 / 뉴스기사 / 정부·공공기관 자료 / 플랫폼 정책 / 기타 중 하나 |
| 원문 URL | 필수: 계정 정보가 없는 `http://` 또는 `https://` 원문 주소 |
| 저자·기관 | 선택. 모르면 빈칸 |
| 발행일 | 선택. `2025`, `2025-03`, `2025-03-15`처럼 아는 범위까지만 입력. 모르면 빈칸 |
| 핵심 메모, 활용 목적 | 선택. 직접 조사한 내용과 활용 목적 |
| 태그 | 선택. `소비자 신뢰도\|구매 의사결정`처럼 `\|`로 여러 태그 구분 |

기존 이름의 태그는 재사용하고 새로운 태그는 자동으로 만듭니다. 태그 앞뒤 공백과 빈 항목을 제거하고 같은 태그는 한 번만 연결합니다. 자료당 최대 50개입니다. 태그 이름 자체에 `|`가 있는 경우 이 방식으로 한 태그를 표현할 수 없으므로 직접 등록·수정 화면을 이용하세요.

제목/자료 제목, 저자·기관/저자/작성 기관, 핵심 메모/핵심 내용 메모, 활용 목적/연구 활용 목적 등 알려진 한국어 이름과 내부 영문 필드를 자동 연결합니다. 같은 등록 항목에 해당하는 열이 둘 이상 있으면 잘못 연결하지 않도록 파일을 거부합니다. 양식에 없는 열은 화면에 안내하고 가져오지 않습니다.

**중복은 기존 자료와 파일 내부 모두 검사**합니다. 원문 URL이 같거나 제목·저자·발행일이 같으면 건너뜁니다(제목·저자는 대소문자 구분 없이 비교, URL은 그대로 비교). 정상 자료가 먼저 나온 순서대로 처리하며 중복으로 건너뛴 자료의 새 메모·태그는 기존 자료에 합치지 않습니다. 기존 자료의 변경은 자료 목록의 수정 화면을 이용하세요. 실행 시 다시 검사하므로 같은 CSV를 두 번 등록해도 자료가 늘어나지 않습니다.

파일은 최대 **10MB·5,000개 자료**입니다. 제목·저자·메모 등 자료 문자열은 기존 등록 규칙대로 보존하고 임의로 내용을 채우지 않습니다. 셀에 쉼표·줄바꿈이 있으면 Excel 등의 CSV 저장 기능이 따옴표 처리를 하도록 하세요. 수식처럼 보이는 값도 앱에서는 텍스트로만 저장하며 목록 CSV 내보내기의 기존 수식 실행 방지 처리를 유지합니다.

| 기능 | 등록·복원 범위 | 검증 상태 |
| --- | --- | --- |
| 자료 등록 → CSV 일괄 등록 | 외부 일반 CSV의 신규 자료·복수 태그. 기존 ID·등록일·검증 정보는 가져오지 않음 | 항상 미검증 |
| 데이터 백업 및 복원 → 전용 CSV 복원 | ReviewLab의 원래 ID·시각·태그·전체 검증 이력 | 신뢰하는 백업의 과거 이력 승계 |

일반 목록 CSV는 표시용으로 수식 위험 문자열에 작은따옴표가 추가될 수 있으므로 원문·이력의 정확한 복구에는 전용 백업을 사용하세요. CSV에 선택적인 **데이터 구분** 열이 있으면 `actual`/`실제 연구자료` 또는 `example`/`예시·연습 자료`/`가상·테스트용`이 현재 모드와 맞아야 합니다. 이 열이 없으면 현재 모드에 등록하므로 모드 선택을 직접 확인하세요.

저장은 자료·새 태그·태그 연결을 **한 트랜잭션**으로 처리합니다. 실패하면 전부 취소하고 기존 자료·검증 이력을 유지합니다. 성공하면 기존 일별 자동 SQLite 백업을 갱신합니다. DB 구조 변경이나 데이터 초기화, 추가 패키지 설치는 필요 없습니다.

## 저장 위치

기본 경로는 사용자 홈 폴더의 `.reviewlab`입니다.

```text
~/.reviewlab/
├── actual/reviewlab.sqlite3      # 실제 연구자료
├── actual/backups/               # 삭제·CSV 복원 전 자동 DB 백업
├── actual/backups/automatic/     # 변경 후 날짜별 최신 DB 사본, 최근 30개
└── example/                     # 동일 구조의 예시·연습 저장소
```

저장 폴더를 바꾸려면 실행 전에 `REVIEWLAB_DATA_DIR`을 설정합니다. 기존 파일이 자동 이동되지는 않습니다. 다른 경로를 선택하면 다른 데이터 저장소를 열게 되므로 현재 화면의 저장 위치를 확인하세요.

```bash
export REVIEWLAB_DATA_DIR=/workspace/reviewlab-data
.venv/bin/python -m streamlit run app.py
```

Windows PowerShell 예: `$env:REVIEWLAB_DATA_DIR = "D:\ReviewLabData"`

DB·CSV·백업은 개인정보가 포함될 수 있으므로 Git에 커밋하지 마세요. 테스트는 임시 DB만 사용합니다. DB는 기본 암호화되지 않습니다. 로컬 모드는 해당 기기에서 편집하는 용도이며 공유 드라이브의 SQLite 동시 편집은 지원하지 않습니다. 기기 간 공유에는 인증된 Supabase 공용 모드를 사용하세요.

## 자동 저장과 자동 백업

자료 저장 버튼을 누르면 즉시 DB에 기록됩니다. 등록·수정·삭제·검증·태그 변경·CSV 복원이 성공하면 별도의 SQLite 사본도 자동 생성합니다. 앱을 열 때 오늘의 백업이 없거나 DB보다 오래됐으면 새로 생성합니다. 앱이 꺼져 있을 때 정해진 시각에 실행하는 방식은 아닙니다.

`backups/automatic/auto-YYYY-MM-DD.sqlite3`에 UTC 날짜별 최신 사본 한 개를 유지하고, 최근 30개 날짜의 자동 백업을 보관합니다. 같은 날 변경하면 그날의 자동 사본을 갱신합니다. 삭제·복원 직전 사본은 다른 경로에 별도로 남겨두며 자동 정리 대상에 포함하지 않습니다. 현재 사본·태그·검증 이력을 모두 보존합니다. 리뷰 프로젝트·검토·분석 실행도 함께 보존합니다.

**설정 및 데이터 관리 → 자동 백업**에서 최근 백업 시각과 폴더를 확인할 수 있습니다. 백업에 실패해도 이미 성공한 자료 저장을 되돌리지는 않으며, 화면에 별도 경고를 표시합니다. 권한·디스크 공간을 확인하고 복원용 CSV도 별도로 보관하세요. 자동 사본은 임시 DB에 먼저 완성·무결성 검사한 후 교체하여 백업 실패 시 이전 사본을 보존합니다.

자동 백업은 같은 컴퓨터에 있으므로 노트북 분실이나 디스크 고장까지 보호하지는 않습니다. 팀이 승인한 별도 저장소나 USB에도 주기적으로 복원용 CSV를 보관하세요. 자동 SQLite 사본을 복구할 때는 아래 DB 사본 조회 방법처럼 새 데이터 경로에 복사하여 먼저 확인합니다. 자동 SQLite 파일을 CSV 복원 화면에 업로드하지 마세요.

## CSV 내보내기와 복원

왼쪽 메뉴의 **데이터 백업 및 복원**을 여세요. 기존 **설정 및 데이터 관리**에서도 같은 CSV 기능을 계속 사용할 수 있습니다.

| 파일 | 목적 | 내용 |
| --- | --- | --- |
| 일반 자료 CSV (전체 목록 CSV 다운로드) | 엑셀 등에서 조회 | 한글 열 이름, 최신 검증 상태·근거, 자료 정보. 복원 불가 |
| ReviewLab 전용 백업 CSV (복원용 CSV 백업 다운로드) | 다른 저장소에 복원 | 모든 자료 ID·원래 입력·등록/수정 시각·태그·전체 검증 이력. JSON을 담은 버전 지정 CSV |

두 파일 모두 UTF-8 BOM을 사용합니다. 파일명에는 현재 데이터 모드·파일 구분·한국 시간(KST)의 다운로드 날짜와 시각을 포함합니다. 예: `reviewlab-actual-backup-2026-10-22_153000-KST.csv`. 화면에서 검색한 일부 자료가 아니라 선택한 모드의 전체 자료를 내보냅니다. 엑셀에서 한글이 깨진다면 “데이터 → 텍스트/CSV에서”로 가져와 UTF-8을 선택하세요. 목록용 CSV는 수식 실행 위험이 있는 셀 앞에 작은따옴표를 붙입니다. 복원용 CSV는 원문을 보존하며 스프레드시트에서 편집하지 마세요.

복원 절차:

1. 백업과 같은 실제/예시 모드를 선택합니다.
2. **데이터 백업 및 복원 → CSV 복원**에서 복원용 CSV를 선택합니다(최대 10MB, 10,000개 자료).
3. **복원 미리보기**에서 전체·추가 예정·중복 건너뛰기·오류 자료 건수를 확인합니다. 기본적으로 같은 ID, 같은 URL 또는 같은 제목·저자·발행일을 건너뜁니다. 잘못된 자료 한 건에 오류가 여러 개 있어도 오류 자료 수에는 한 건으로 셉니다. 파일 자체의 형식이 잘못되어 자료 수를 셀 수 없다면 파일 오류와 “확인 불가”로 표시합니다.
4. 의도적으로 중복 등록했던 자료까지 보존하려면 **서로 다른 ID의 중복 후보도 복원**을 선택하세요. 같은 ID는 이 옵션과 무관하게 건너뜁니다.
5. 오류가 0건일 때 추가 복원 및 신뢰하는 과거 검증 이력의 승계에 체크한 뒤 **CSV 복원 실행**을 누릅니다.
6. 완료 안내의 추가·중복 건수를 확인한 뒤 **자료 목록**에서 복원한 제목을 검색합니다. 기존 검색 필터가 남아 있다면 전체로 변경하세요.

오류가 하나라도 있으면 정상 자료를 일부만 가져오지 않고 전체 복원을 차단합니다. 실행 직전에도 파일 내용을 다시 검사하고 실제 DB를 기준으로 중복 여부를 다시 계산합니다. 미리보기는 DB에 자료를 추가하지 않습니다. 기존 백업 버전(`reviewlab-backup-v1`)은 계속 지원하며 참고문헌 CSV 복원은 기존 자료를 초기화하지 않습니다.

기존 자료는 덮어쓰지 않습니다. 수정된 백업을 같은 저장소에 넣어도 기존 ID의 내용은 업데이트되지 않습니다. 정확한 백업 시점의 사본이 필요하면 **새로운 빈 데이터 경로**에서 복원하고, 의도적 중복이 있다면 중복 후보 복원 옵션을 사용하세요. 다른 경로의 원본 데이터는 유지하세요.

손상된 형식, 잘못된 값, 서로 다른 실제/예시 모드는 쓰기 전에 거부합니다. 쓰기는 하나의 트랜잭션으로 처리하며 실패하면 전체 취소합니다. 태그는 이름으로 병합하고 새 이름은 추가합니다. CSV 파일은 서명된 증명서가 아니므로 신뢰하는 백업만 복원하세요. 앱은 복원 중 원문을 새로 검증하지 않습니다.

삭제와 CSV 복원 전에 SQLite 백업 API로 `backups`에 DB 사본을 만듭니다. 이 사본의 조회가 필요하면 앱을 종료한 뒤 사본을 **새 데이터 루트의 같은 모드 폴더**에 `reviewlab.sqlite3`라는 이름으로 복사하여 그 경로로 실행하세요. 실행 중인 원본 DB를 교체하지 마세요. 일상적인 백업·복원은 UI의 CSV 기능을 권장합니다. 과거 백업의 삭제된 자료도 팀의 보존 정책에 맞춰 관리해야 합니다.

## 제약 및 다음 단계

- 3~5단계 기능, 크롤링, PDF 보관, 외부 AI API는 구현 범위 밖입니다. 공용 모드에는 로그인과 충돌 감지를 제공하며 대규모 동시 편집·공개 웹 배포는 별도 검증이 필요합니다.
- 전용 백업 CSV는 전체 이력 복원용입니다. 일반 참고문헌 CSV는 자료 등록에서 알려진 열 이름을 자동 연결하여 신규 등록할 수 있으며 사용자 지정 열 매핑 화면은 제공하지 않습니다.
- 저자·기관명은 입력한 단일 문자열을 그대로 보존합니다. 저자별 구조화와 인용 양식 자동 생성은 향후 확장 사항입니다.
- 검색·집계는 소규모 자료를 메모리에 읽어 처리합니다. 대규모 데이터 성능과 브라우저 수동 조작·Windows/macOS 실기 검증은 별도 수행해야 합니다.
- 3단계 설문은 리뷰와 별도 테이블에 문항·척도·결측 코드·다중 응답·동의 범위를 정의해야 합니다. 리뷰의 분모와 설문 응답자 수를 혼용하지 않습니다.

## 2단계 리뷰 분석 사용 방법

왼쪽 **리뷰 분석** 메뉴에 다음 6개 화면이 있습니다. 기존 참고문헌 메뉴는 그대로 사용할 수 있습니다.

1. **리뷰 데이터 업로드**: 새 프로젝트 이름과 별점 척도(기본 가정 0~5)를 정합니다. 척도가 다른 플랫폼은 프로젝트를 분리합니다. CSV를 올리고 인코딩(UTF-8 BOM 또는 CP949)·열 연결·추가/중복/오류 건수를 확인합니다. 수집 경위와 이용 권한·개인정보 확인 후 **리뷰 저장**을 누릅니다.
2. **리뷰 목록**: 플랫폼·별점·작성일·이벤트 언급·키워드로 검색합니다. 상세 원본과 연구자가 추가한 메모를 따로 확인합니다. 메모 추가는 원문을 변경하지 않습니다.
3. **리뷰 통계 분석**: 플랫폼별 별점, 이벤트 비율, 별점별 길이, 날짜별 개수, 선택 기준 비교, 단어 수 분포를 봅니다. 업종별 표와 지표별 분모도 제공하며 각 그래프 아래에서 **PNG 다운로드**가 가능합니다.
4. **리뷰 패턴 탐색**: 동일 문구, 반복되는 2~3단어 어구, 이벤트·광고 관련 표현, 문자 유사도 후보를 확인합니다. 자동 탐색 결과는 가짜·AI 생성 여부를 판정하지 않습니다.
5. **리뷰 검토 관리**: 미검토/검토 중/검토 완료/분석 제외와 검토자·날짜·판단 근거·메모를 기록합니다. 완료·제외에는 근거가 필수입니다. 이력은 추가되며 원본을 덮어쓰지 않습니다.
6. **분석 결과 내보내기**: 전체 리뷰 목록 CSV, 현재 필터의 분석 결과 CSV, 프로젝트 전용 백업 CSV를 받거나 백업을 복원합니다. 패턴/내보내기 화면의 **현재 분석 조건·결과 기록 저장**으로 입력 리뷰 ID와 결과·필터·도구 버전을 DB에 남깁니다.

프로젝트 참고문헌 연결은 업로드 또는 통계 화면의 **프로젝트에 참고문헌 연결**에서 합니다. 연결된 자료가 결과를 입증한다는 뜻은 아닙니다. 참고문헌이 삭제되면 링크는 미연결 상태가 되고 연결 당시 제목·URL은 유지됩니다.

### 리뷰 CSV 입력 규칙

샘플: [`examples/reviews_example.csv`](examples/reviews_example.csv). 앱의 **가상·테스트용 샘플 CSV** 버튼에서도 같은 파일을 받습니다. 12행 모두 허구이며 **예시·연습 자료** 모드에서만 저장할 수 있습니다. 예시 내용을 논문 근거로 사용하지 마세요.

| 열 | 규칙 |
| --- | --- |
| 리뷰 고유 ID, 플랫폼명, 업종 | 선택. 플랫폼+리뷰 ID가 같으면 이미 있는 리뷰를 유지하고 건너뜀 |
| 별점 | 선택. 프로젝트가 지정한 범위의 유한한 숫자 |
| 리뷰 내용 | 별점 또는 내용 중 하나는 필수 |
| 리뷰 작성일, 수집일 | 선택. 미래가 아닌 `YYYY-MM-DD` |
| 리뷰 이벤트 언급 여부, 광고·협찬 표시 여부 | `예` / `아니오` / `미확인`. 본문으로 자동 추정하지 않음 |
| 원문 URL | 선택. 계정 정보 없는 HTTP(S) 주소, 자동 접속하지 않음 |
| 연구자 메모 | 원본 CSV에 들어 있던 메모. 업로드 후 추가 메모와 분리 |
| 데이터 구분 | 선택. 실제는 `실제 연구자료`, 예시는 `가상·테스트용`. 모드와 다르면 거부 |

한국어 열 또는 내부 영문 열 이름은 자동 연결하며 다른 이름은 화면에서 직접 연결합니다. 작성자 실명·계정·연락처 열은 기본 저장 대상에 없습니다. 추가 열은 버립니다. 내용·메모 안의 개인정보를 자동 탐지하거나 지우지는 않으므로 업로드 전에 직접 제거하세요. 원본 CSV 파일 자체는 앱에 보관하지 않고 허용된 원본 필드·파일 해시·매핑·인코딩·수집 경위만 저장합니다. 원본 파일은 팀이 승인한 위치에 보관하세요.

공란/`미확인`/`unknown`은 결측으로 처리합니다. 원문 문자열은 별도 보존하며 분석용 문자열은 앞뒤 공백을 제거합니다. ID가 없으면 정규화된 리뷰 필드 전체(연구자 메모 제외)가 일치하는 행을 건너뜁니다. 같은 문구라도 ID가 다르면 보존하여 패턴 탐색에서 비교합니다. 오류 행이 하나라도 있으면 전체 업로드를 차단하며 정상 행만 조용히 저장하지 않습니다.

한 업로드 파일은 **10MB·5,000행**, 프로젝트는 **5,000리뷰**까지 지원합니다. 유사 표현 비교는 저장 순서 첫 **200건**, 각 내용 첫 **1,000자**, 문자 3-gram Jaccard 유사도(기본 0.8)로 제한합니다. 정확 문구·반복 어구·표현 탐색은 현재 선택된 전체 리뷰 대상입니다. 반복 어구는 리뷰별 한 번만 세며 상위 50개를 표시합니다.

### 통계 해석과 내보내기

분석 제외 상태는 기본 필터에서 제외합니다. 기간 필터를 쓰면 날짜 미확인도 기본 제외하지만 체크하여 포함할 수 있습니다. 날짜 그래프는 알려진 날짜만 사용하고, 관측이 없는 날짜를 리뷰 0건으로 채우지 않습니다. 내용이 없는 리뷰는 길이/단어 수에서 제외하고, 별점이 없는 리뷰도 내용이 있으면 `미확인` 별점 집단의 길이 계산에는 포함합니다. 단어 수는 한국어 형태소 수가 아니라 공백으로 나눈 어절 수입니다.

이벤트 그래프는 **전체 선택 리뷰를 분모**로 예/아니오/미확인 비율을 표시합니다. 화면에는 여부가 확인된 리뷰만 분모로 한 비율도 별도 표시합니다. 평균 별점은 별점 관측 건수, 중앙 길이는 내용 관측 건수가 분모입니다. 30건 미만이면 표본 부족 안내를 표시하지만 30건 이상도 대표성·유의성·인과관계를 보장하지 않습니다.

PNG는 Plotly와 같은 집계표로 Matplotlib에서 렌더링합니다. 따라서 화면과 스타일은 다를 수 있으며 대화형 조작은 포함되지 않습니다. 별도 Chrome 설치는 필요 없습니다. 한글 폰트는 고정 버전 `koreanize-matplotlib`의 NanumGothic 파일을 사용합니다. Python 3.12에서 호환되지 않는 해당 패키지의 초기화 코드는 호출하지 않습니다.

| 파일 | 범위 | 복원 |
| --- | --- | --- |
| 기존 일반 자료 CSV | 참고문헌 전체 목록 | 불가 |
| 기존 참고문헌 전용 백업 CSV | 참고문헌·태그·전체 출처 검증 이력 | 기존 **데이터 백업 및 복원** 메뉴 |
| 리뷰 목록 CSV | 선택 프로젝트 전체 리뷰·원본 필드·현재 검토·추가 메모. 화면 필터와 무관 | 불가 |
| 분석 결과 CSV | 현재 필터의 집계·패턴과 조건 JSON. `분석표/행/필드/값`의 긴 표 형식 | 불가 |
| 리뷰 전용 백업 CSV | 프로젝트 전체 리뷰·원본·수집 기록·모든 메모/검토·저장한 분석 실행·참고문헌 연결 기록 | **리뷰 분석 → 분석 결과 내보내기** |

모두 UTF-8 BOM이며 모드·KST 날짜가 파일명에 포함됩니다. Chrome에서 다운로드 후 `Ctrl+J`로 저장 위치를 확인하세요. 참고문헌 백업에 리뷰가 포함되지는 않습니다. 일별 SQLite 자동 백업에는 두 단계의 데이터가 모두 들어갑니다.

리뷰 복원은 백업과 같은 모드에서 파일(최대 50MB)을 올리고 추가/중복/오류 미리보기를 확인한 뒤 승계 체크와 실행 버튼을 누릅니다. **같은 프로젝트 ID가 있으면 프로젝트 전체를 건너뜁니다.** 수정된 백업의 병합·덮어쓰기는 지원하지 않습니다. 백업 시점 그대로 별도 확인하려면 새로운 데이터 루트에서 실행해 복원하세요. 서로 다른 프로젝트의 같은 리뷰 내용은 자동 병합하지 않습니다.

참고문헌 자체는 리뷰 백업에 들어 있지 않습니다. 새 저장소에서는 참고문헌 백업을 먼저 복원하면 ID로 연결됩니다. 연결할 자료가 없으면 제목·URL 기록만 미연결 상태로 보존합니다. 나중에 참고문헌을 복원했다면 프로젝트 참고문헌 연결에서 다시 선택해 연결할 수 있습니다. 복원은 백업의 과거 연구자 판단을 승계할 뿐 새로 검증하지 않습니다.

### 기존 Windows 앱 업데이트

1. 실행 중인 검은 터미널 창에서 `Ctrl+C`로 종료합니다.
2. 업데이트된 저장소 ZIP을 새 폴더에 모두 압축 해제합니다.
3. 새 폴더의 `Start_ReviewLab.cmd`를 실행합니다. 새 패키지를 설치하고 서버를 시작합니다.
4. 같은 Windows 계정에서 기본 저장 경로를 유지하면 기존 `사용자 폴더\.reviewlab` DB를 계속 사용합니다. 별도 `REVIEWLAB_DATA_DIR`을 설정했던 경우 동일 경로를 사용하세요.

새 버전은 기존 DB를 SQLite 백업 API로 복사한 뒤 스키마 2 테이블만 추가합니다. 실패하면 마이그레이션을 취소하며 참고문헌을 초기화하지 않습니다. 이미 스키마 2인 DB를 이전 버전 앱으로 열면 버전 오류로 중단됩니다. 이전 앱으로 원본 DB를 강제 수정하지 마세요.
